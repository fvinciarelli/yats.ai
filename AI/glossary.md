# Glossary

## A

**AbstractAnalyzer:** Base class all language analyzers extend. Provides `createSymbol()`, `createRelationship()`, `makeId()` helpers.

**AnalyzerFactory:** Registry that maps `Language` → `LanguageAnalyzer` implementation. Dispatches analysis by file language.

**APOC:** Neo4j plugin library (Awesome Procedures on Cypher). Used for advanced graph operations.

## C

**Collection (Qdrant):** A named vector space with a fixed dimension and distance metric. Two collections exist: `code` (768d) and `documentation` (768d).

**Content Hash:** SHA256 hex string of a symbol's `sourceSnippet`. Used by `SymbolDiffer` for change detection during incremental indexing.

**Convention Detection:** Inferring architectural roles from naming patterns (e.g., `*Controller` → CONTROLLER, `*Service` → SERVICE) and framework decorators (`@Entity()` → ENTITY).

**Cypher:** Neo4j's query language (like SQL for graphs). Used in `Neo4jGraphRepository` for all graph operations.

## D

**DTO (Data Transfer Object):** Simple objects that carry data between layers. Located in `shared/src/dto/`.

## E

**Embedding:** A dense vector (768 or 1536 floats) representing the semantic meaning of a symbol or query. Generated by Ollama or OpenAI.

**EmbeddingGenerator:** Interface for embedding providers. Two implementations: `OllamaEmbeddingGenerator`, `OpenAIEmbeddingGenerator`.

## G

**Graph Expansion:** Multi-hop traversal from seed symbol IDs through Neo4j relationships. E.g., from a Service, expand 1-hop to find its Controller, Repository, and Tests.

**GraphRepository:** Interface for Neo4j operations. Implemented by `Neo4jGraphRepository`.

## H

**Hybrid Retrieval:** Combining vector similarity search (Qdrant) with graph expansion (Neo4j) to produce context for LLMs.

## I

**Indexing Pipeline:** The full flow: walk files → detect language → analyze → embed → store in Neo4j + Qdrant.

## J

**JSON-RPC:** The protocol MCP uses. Requests and responses are JSON objects with `jsonrpc`, `id`, `method`/`result`.

## L

**LanguageAnalyzer:** Interface every parser plugin must implement. Single method: `analyze(filePath, content, repoName) → AnalysisResult`.

**LibCST:** Concrete Syntax Tree library for Python. Used by the Python analyzer bridge.

## M

**MCP (Model Context Protocol):** Open protocol by Anthropic that standardizes AI-tool communication. This project acts as an MCP server.

**MemorySymbolStore:** Transient in-memory store for symbols and relationships during a single indexing run.

## N

**Neo4j:** Graph database used to store symbols as nodes and relationships as edges. Enables graph traversal queries.

**nomic-embed-text:** The default embedding model used via Ollama. Produces 768-dimensional vectors.

## P

**Payload Index (Qdrant):** Indexes on vector metadata fields (language, repository, kind) enabling filtered search.

**Port (Hexagonal Architecture):** An interface defined in the domain layer (`shared/ports/`) implemented by infrastructure adapters.

**PHP-Parser:** Nikic's PHP parser library. Used by the PHP analyzer bridge.

## Q

**Qdrant:** Vector database used for semantic search. Stores embeddings with metadata payloads.

## R

**RankedContextItem:** The result type from retrieval: `{ symbol, score, source, relevanceReason, snippet }`.

**Relationship:** A directed edge between two symbols: `{ id, sourceSymbolId, targetSymbolId, kind, metadata }`.

**Retriever:** Interface for the hybrid search pipeline. Implemented by `RetrieverService`.

**Roslyn:** Microsoft's .NET compiler platform. Used by the C# analyzer (planned, not yet implemented).

## S

**SourceLocation:** Pinpoints a symbol: `{ repository, relativePath, startLine, endLine, startColumn, endColumn }`.

**Source Snippet:** The first ~80 lines of a symbol's source code, used as input for embedding generation.

**Symbol:** The universal representation of a code element: `{ id, name, kind, location, language, namespace, ... }`.

**SymbolId:** A branded string type. Format: `{repository}::{relativePath}::{symbolPath}`. Guarantees global uniqueness.

**SymbolKind:** Enum of 39 values classifying what kind of code element a symbol is (class, method, controller, service, etc.).

**SymbolStore:** Interface for transient symbol storage during indexing. Implemented by `MemorySymbolStore`.

## T

**Token Budget:** Maximum token count for results returned to the LLM. The retriever uses `TokenBudgetService` to fit results within budget (default: 8000 tokens).

**Tree-sitter:** Incremental parsing library. Used as a fallback analyzer for all languages.

**Tsyringe:** Microsoft's lightweight DI container for TypeScript. Used for dependency injection.

## V

**VectorRepository:** Interface for Qdrant operations. Implemented by `QdrantVectorRepository`.

## Y

**YATS (Yet Another Token Saver):** The project name. Indexes codebases, builds knowledge graphs, and serves MCP tools so LLMs query code without reading raw files — saving tokens.
