# Spike — Per-repo indexing config + `INDEX_DOCS` hardcode

**Date:** 2026-09-21
**Status:** proposed (awaiting confirmation before implementation)

Goal: let each repository control which folders and docs YATS indexes for it,
and fix config knobs that are hardcoded instead of user-overridable.

---

## 1. Current state (facts)

### Config sources, by layer

| Layer | File | Read by | Contents |
|---|---|---|---|
| Machine config | `~/.yats/.env` | CLI (`yats index` via `loadYatsEnv`, since 0.5.0/P4) **and** compose interpolation (docker compose auto-loads the `.env` next to `~/.yats/docker-compose.yml`) | `DOC_EXTENSIONS`, `SKIP_EXTENSIONS`, `IGNORED_DIRS`, embedding keys |
| Compose | `~/.yats/docker-compose.yml` (generated by `yats setup`) | container env | hardcodes `INDEX_DOCS=true`, `DOC_MAX_FILES=300`, `EMBEDDING_BATCH_SIZE=200`; interpolates the rest from `~/.yats/.env` |
| Server code | `indexer.service.ts` | `process.env` at request time | `INDEX_DOCS` (docs all/none), `DOC_EXTENSIONS` (what counts as a doc), `DOC_PATTERNS` + `DOC_MAX_FILES` (legacy full-pipeline only — **dead in the current CLI flow**) |
| CLI code | `indexer.js` | `~/.yats/.env` + flags | walk filters (`IGNORED_DIRS`, `SKIP_EXTENSIONS`), `--skip-docs` vs `DOC_EXTENSIONS` |
| CLI flags | per run | — | only `--skip-docs` exists |

### Consequences

1. **Everything is global per machine.** One machine-wide `IGNORED_DIRS` /
   `DOC_EXTENSIONS` applies to every repo indexed from it. No way to say
   "for *this* repo, index docs, but for *that* repo, don't" or "ignore the
   `sandbox/` folder only here".
2. **No doc whitelist on the CLI path.** Every file matching `DOC_EXTENSIONS`
   is sent and indexed (sections → Qdrant). `DOC_PATTERNS` (the only
   whitelist mechanism that ever existed) only runs in the server-side full
   pipeline, which `yats index` no longer uses since v0.4.0.
3. **`INDEX_DOCS` is hardcoded** in two places:
   - `setup.js` compose template: `- INDEX_DOCS=__INDEX_DOCS__` (baked at
     setup time; editing `~/.yats/.env` afterwards has no effect).
   - Deployed `~/.yats/docker-compose.yml`: `- INDEX_DOCS=true`.
   - The repo's own `docker/docker-compose.yml` doesn't even pass
     `INDEX_DOCS`/`DOC_EXTENSIONS`/`DOC_MAX_FILES` at all.
4. `EMBEDDING_BATCH_SIZE` has the same hardcode pattern (minor, same fix).

---

## 2. Design proposal

### 2.1 Per-repo config — `.yats/config.json` in the repo root

**File:** `.yats/config.json` (JSON, zero deps for the CLI). Committed to the repo so
the behavior is team-shared and reviewable.

**Schema (all keys optional):**

```json
{
  "indexDocs": false,
  "docExtensions": [".md"],
  "docPatterns": ["docs/", "README.md", "AI/architecture.md"],
  "ignoredDirs": ["sandbox", "generated"],
  "skipExtensions": [".snap", ".golden"]
}
```

**Semantics:**

| Key | Meaning | vs global |
|---|---|---|
| `ignoredDirs` | extra dirs to skip while walking | **union** with `~/.yats/.env` `IGNORED_DIRS` |
| `skipExtensions` | extra suffixes to skip | **union** |
| `docExtensions` | which extensions count as docs *for this repo* | **replaces** `DOC_EXTENSIONS` |
| `docPatterns` | whitelist: only doc files whose repo-relative path matches one of these prefixes are sent | filters *within* doc files; no match → no docs sent |
| `indexDocs` | `false` = skip all doc files (same effect as `--skip-docs`, automatic) | narrows only |

**Rule: a repo can only narrow, never widen, the machine's global config.**
Rationale: predictable and safe; e.g. if the server runs with global
`INDEX_DOCS=false`, docs are dropped server-side regardless, so a repo cannot
re-enable them — the CLI must not pretend otherwise.

**Precedence:** CLI flags (`--skip-docs`) > `.yats/config.json` > `~/.yats/.env` >
built-in defaults.

**Malformed / missing file:** missing → defaults; unparseable JSON or wrong
types → warn on stderr and ignore the file (never fail an index run).

**Why CLI-side (not server-side):**
- The CLI already walks the host filesystem and already owns filtering
  (`IGNORED_DIRS`, `SKIP_EXTENSIONS`, `--skip-docs`). Doc whitelisting is
  simply "don't send files that don't match" — the server needs **zero
  changes**; it keeps indexing whatever doc files arrive.
- The server never walks files; asking it to make per-repo filtering
  decisions would require shipping repo-scoped settings to it (new state,
  new endpoints) for no functional gain.

### 2.2 `yats watch` must apply the same filters

`watch.js` sends added/modified files from git diffs. It must load
`.yats/config.json` and apply the same filtering (docs skipped when
`indexDocs=false`, `docPatterns` honored, extra ignores respected). The full
re-index fallback already goes through `indexRepo`, which would apply it
automatically.

### 2.3 `INDEX_DOCS` (and siblings) hardcode fix

- **`setup.js` template:**
  ```
  - INDEX_DOCS=${INDEX_DOCS:-__INDEX_DOCS__}
  - DOC_MAX_FILES=${DOC_MAX_FILES:-__DOC_MAX__}
  ```
  The wizard choice remains the default; users can override later from
  `~/.yats/.env` without re-running setup.
- **Repo's dev `docker/docker-compose.yml`:** add the missing doc env block
  for parity:
  ```
  - INDEX_DOCS=${INDEX_DOCS:-true}
  - DOC_MAX_FILES=${DOC_MAX_FILES:-300}
  - DOC_EXTENSIONS=${DOC_EXTENSIONS:-.md,.mdx,.rst,.txt,.adoc,.org,.wiki,.readme}
  ```
- **`EMBEDDING_BATCH_SIZE`:** same pattern (`${EMBEDDING_BATCH_SIZE:-__BATCH_SIZE__}`) — included since it's the same one-line class of bug.
- Deployed machines: after the fix, `INDEX_DOCS=false` in `~/.yats/.env` +
  `docker compose -p yats up -d yats` to recreate the container.

### 2.4 Explicitly out of scope

- Server-side per-repo settings (Neo4j-stored options, new endpoints).
- Reviving `DOC_PATTERNS` server-side (legacy pipeline path).
- Per-repo embedding/provider config.

## 3. Implementation plan (when confirmed)

1. `indexer.js`: `loadRepoConfig(repoPath)` + merge with `loadYatsEnv()`;
   apply in `indexRepo` (walk filter + doc whitelist).
2. `watch.js`: load repo config once at startup; apply in `applyDiff`
   (added/modified) and live mode.
3. `setup.js` + `docker/docker-compose.yml`: `${VAR:-default}` fixes.
4. Tests:
   - `loadRepoConfig`: missing file, valid, malformed JSON, wrong types.
   - Merge semantics: union vs replace, precedence with `--skip-docs`.
   - `docPatterns` whitelist (prefix match, `docs/` dir prefix).
   - watch integration: diff flow with `.yats/config.json` skips doc files.
   - setup template: generated compose contains `${INDEX_DOCS:-...}`.
5. Docs: README section + CHANGELOG.

## 4. Open questions

**Resolved with the user (2026-09-21):**

1. File name: **`.yats/config.json`** (inside a `.yats/` dir in the repo root).
2. `docPatterns`: **prefix-only** (no globs).
3. Malformed config: **stop the process and ask whether to fix it.** Never
   index with a broken config (a wrong filter could mean indexing something
   huge). TTY: prompt to open `$EDITOR`, re-validate, and retry in a loop.
   Non-TTY (the normal case — an AI agent runs `yats index`): exit 1 with a
   message written for the AI client, so it can fix the file and re-run while
   informing the user. The message includes the exact schema, why the run was
   stopped, and the escape hatches (fix + retry, delete the file to fall back
   to machine defaults, or `--no-config`).
